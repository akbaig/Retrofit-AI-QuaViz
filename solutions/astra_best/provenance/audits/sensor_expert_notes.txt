Shared sensor expert: implementation and measured development behavior
=====================================================================

Interface
---------
SensorExpert().fit(X, meta, events)
SensorExpert.predict(X, meta) -> four SENSOR_* score columns, same row index.
The reference experiments pass hist_01.transform(X, meta), using its frozen
healthy-reference regressors. Supply a chronological available history prefix
for each asset. All historical reference calculations are past-only.

This is a shared classifier across sensor tags: a current sensor and a pressure
sensor are represented by the same generic feature schema. IDs only isolate
histories and match training events; channel names only select measurements and
match event.sensor_tag. Neither is an inference feature. Profiles, static ratings,
calendar times, hidden schedules and fault labels are not inference features.

Features compare observed within-minute noise and between-update variability
with robust, delayed historical references; characterize flat readings, jumps
and trends; and measure departures from physical consistency or learned healthy
expectations. References use observations at least 60 minutes old. Temperature,
current and pressure units cancel in the generic ratios. A load-dependent
electrical power-factor consistency check also supplies evidence before a
historical reference has matured. It is approximate, not a direct alert rule.

Targets match the event's affected sensor, rather than labeling every channel
positive. Pre-detectable and unobservable intervals for that target fault are
unknown. Other sensors and machine-fault intervals provide negative examples.
Predict pools each fault's score by maximum across currently observed channels.
These are uncalibrated scores; max pooling introduces a multiple-channel false-
alarm opportunity, so select thresholds/persistence after pooling.

Six tests pass: target specificity/unknown intervals, prefix causality and no
identity columns, unit/channel invariance, isolated asset histories, a learned
noise model transferring to an unseen sensor tag, and missing-channel masking.

sensor_expert_01
----------------
Fit on original_train + train + train_balanced, after frozen hist_01 transform.
76,615 sampled channel examples; 47 generic features; four independently trained
140-iteration histogram gradient-boosted classifiers (15 leaves, minimum leaf35,
L2=3, learning rate .06). Positive sampling/event weights balance training events.

sensor_expert_02 changes
-----------------------
Adds train_crossed machine/healthy tracks as hard negatives. Negative sampling
balances assets; positive fitting weights balance events without applying the
inverse-duration weighting twice. Adds deviations from the sensor's historical
learned-residual bias and historical electrical-consistency bias, plus slope and
trend directionality. This aims to distinguish an emerging offset from a static
asset bias. Original01 models keep their original feature columns.

Noise classification uses only generic variance/step features, data support,
operating transitions and trend directionality. Increasing normalized within-
minute noise ratios have monotone constraints. Stuck classification uses flatness,
update counts and context, excluding unrelated physical offsets. Drift/shift
retain the broader generic consistency and temporal feature set.

All numerical results for each subsequent run are saved in its analysis.json;
official benchmark scoring remains the parent runner's responsibility.

Observed-data mismatch, not a scoring adjustment
------------------------------------------------
The synthetic development crest-noise event on asset02 is marked observable=True
but has no observed target crest values, no within-minute std, and zero actual
target updates throughout its event interval. A predictor cannot infer that
unobserved noise from that channel. The event and official scorer were NOT changed
or suppressed. This mismatch should be disclosed separately from performance.

The augmentation owner independently verified that new train_sensor_crossed
events contain actual target observations: at least593 active RUNNING minutes
and220 clean prefault reporting minutes per event. Those are training additions,
not replacements or modifications to evaluation labels.
